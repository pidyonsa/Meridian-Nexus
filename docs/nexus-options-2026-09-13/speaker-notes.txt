RISK METHOD
This is a qualitative decision assessment using the supplied email, handovers, Meridian's requirements and primary cloud references. No penetration test, SLA audit, throughput benchmark, contract review or verified control inventory was performed. H indicates a material impact with an unresolved scope/control/evidence gate; M indicates manageable exposure that still requires evidence. Missing evidence is not evidence of a security breach. Ratings are not calibrated probabilities and should not be added into an artificial vendor score. Residual risk is not rated down until controls are tested.

WHY THE RATINGS DIFFER
Catalyst has a lower immediate feed-transition exposure because keeping the existing service avoids replacing the pipeline now; this is not a freshness/performance guarantee. Its email omits a full Nexus integration scope and full-history/raw-export rights. Geo introduces both supplier concentration and an unpriced integration/data migration, so acceptance gates are material. Meridian can reuse current Nexus work and control the cloud account but must actually provide engineering cover and operate security; ownership does not remove upstream dependence or cloud lock-in. A single Johannesburg region leaves a regional outage risk even with local backup copies.

REQUIRED SECURITY AND PRIVACY CONTROLS
Meridian must define role/client/store access at the backend, including exports and AI retrieval; administrators need MFA and controlled emergency access. No supplier API keys in browser bundles, shared prompts or public source control. Use bounded workload identities, private storage, short-lived download access, TLS, encryption, audit logs and secret rotation. Enforce data retention and limit GPS, photos, message data and customer records to business need. POPIA responsibilities are not outsourced merely by selecting a host; agree operator terms, incident notification and any external processing with the Information Officer. Legal counsel should validate the application to Meridian; this document is not a compliance certification. [POPIA ss.19-22,72]

IP AND EXIT
Meridian should own assigned bespoke Nexus code, configuration, tests and documentation, subject to employment/contractor agreements and third-party licences. Cloud-provider software remains the provider's IP; Google's terms distinguish customer data/applications from Google services. A white-label portal or paying for an API does not automatically convey provider code. Source retailer data may be licensed rather than unconditionally owned: secure rights to retain, combine, backfill, export and use authorised history after supplier termination. Obtain practical bulk export, data dictionary, mappings, credential transfer/revocation, transition assistance and deletion confirmation. Repositories and billing/recovery contacts should be under Meridian corporate control with at least two named custodians. [Google terms 5.1]

AI CAUTION IN E1
The supplier warns about AI-built systems using API access. Treat this as a real implementation-security concern, not proof that every AI-assisted application is unsafe. Review generated code; run secrets/dependency checks and tenant-isolation tests; keep credentials away from models; require human approval before write actions. A read-only API prevents modifications but does not prevent unauthorised reading. Runtime AI must use the current user's permissions and be tested for leakage and unsupported answers.

RECOVERY AND OPERATIONS
Agree business recovery targets and demonstrated restores rather than using a provider availability headline as an application guarantee. Candidate targets for analytical reporting, for approval only: restored within 4 hours for a recoverable application incident, no more than one daily refresh lost. These do not apply to a whole-region outage or to accepted orders, which need stricter no-loss/idempotency controls. Do not promise these targets before testing and funding them. Keep job checkpoints, retry/duplicate handling and visible last-success timestamps. Set cost alerts plus query/API quotas and spending response procedures; an alerts-only budget is not a hard limit.
