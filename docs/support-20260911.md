# Nexus Support

## Access and Workflow

- Staff: sidebar **Support**, or `https://meridian-nexus.web.app/#support`.
- Administrators: **Admin > Support**, or the **Admin Support** button in My tickets.
- All active, registered Nexus staff have Support access by default. Clients and unregistered accounts are rejected. Staff see only their own tickets; active administrators see all tickets.
- Submit an issue with its module, priority, description and optional attachments. Reply to a ticket, inspect its history, or reopen a resolved/closed ticket.
- Administrators can filter all/assigned/personal queues, assign to another active administrator, update priority/status and record a resolution note. Resolving/closing requires a note. Status updates retain an immutable conversation entry.
- Queues paginate 50 records at a time, newest update first. Conversations paginate backwards in groups of 50. Refresh retrieves current status; ticket-reference lookup is permission checked.
- This release does not send Support email/push notifications. Tickets are retained for audit rather than hard-deleted through the UI.

## Private Attachments and Controls

- Maximum three attachments per submission, 3 MB each: PNG, JPEG, WebP, PDF, TXT and CSV.
- Server validates file signatures, sizes, names and text encoding. This is not a malware-scanning service; treat downloaded documents as untrusted.
- Storage prefix: `support-ticket-attachments/`. No public objects, Firebase download tokens or signed download URLs. Downloads go through the callable and recheck current ticket/account permissions.
- Existing deployed Firestore and Storage rules deny direct browser access to Support data. Those rules were not widened or redeployed.
- The existing runtime service account received object-admin access only on this new prefix; all pre-existing bucket bindings were preserved.
- Current Auth account, current custom claims, current staff profile and revocation time are checked for each call. Admin updates also verify the assignee and use revision checks against stale edits.
- Submission IDs prevent duplicate tickets/replies when retrying the same open form. File writes and ticket/message commits use reservations; failed uploads cannot create partial tickets.
- Per-account limits: 30 new mutations/minute, 20 new tickets/day, 30 MB attachments/day. Daily quota boundaries are UTC.

## Backend and Maintenance

- Firestore collections: `supportTickets`, ticket `messages` subcollections, `supportOperations`, `supportQuotas`.
- Callable: `meridianSupport`. Cleanup scheduler: `cleanupMeridianSupportUploads`, daily 03:40 Africa/Johannesburg. Cleanup deletes only expired, unbound Support uploads, up to 100 operations per run; it never deletes completed ticket evidence.
- Separate Firebase codebase **support**, Node 22, deployed through `functions/support-entry.js`. The isolated package locks Firebase Admin 14.4.0 and Firebase Functions 7.3.2.
- Runtime limits: callable max three instances, 512 MiB, concurrency 20, 120 seconds. Cleanup max one instance, 256 MiB, 120 seconds. Scheduler invocation is IAM protected; the callable requires Nexus Auth inside the handler.
- `npm audit` on the isolated package reports two moderate findings from gaxios/uuid. Inspection found gaxios uses UUID v4 without a supplied buffer, not the advisory's v3/v5/v6 buffer path. Compatible audit fixes do not remove this transitive finding. Recheck when the upstream dependency updates. No high/critical findings remained in the isolated package.
